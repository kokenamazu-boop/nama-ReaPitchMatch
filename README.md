# nama-ReaPitchMatch

[![tests](https://github.com/kokenamazu-boop/nama-ReaPitchMatch/actions/workflows/tests.yml/badge.svg)](https://github.com/kokenamazu-boop/nama-ReaPitchMatch/actions/workflows/tests.yml)

REAPERで、**ファイル名に書かれた音名**を読み取り、選択した音声アイテムを**指定した音程**へ移調するReaScriptです。人力ボーカル素材の音程合わせを、1回の実行でまとめて行うことを目的にしています。

- 例：`り_D4_30.wav` を `E4` へ移調
- 例：`あ_F#3.wav` を `G3` へ移調
- MIDIエディタで選択したノートを、目標音として自動入力
- 必要に応じて元音声を解析し、**セント単位のズレ**を補正
- 選択アイテムの**アクティブテイクだけ**を対象にし、元の音声ファイルは書き換えない
- SWS / ReaImGui / 外部ライブラリは不要

## 動作環境

- REAPER 7系を推奨（REAPER内蔵のLua 5.4を使用）
- ピッチシフトモード **Soloist** が利用できること
- Windowsを想定しています。macOSでもLua自体は動きますが、UIフォントは環境に合わせて調整してください。

## インストール

### ReaPackを使う場合

1. REAPERで `Extensions → ReaPack → Import repositories...` を開きます。
2. 次のURLを追加します。

   ```
   https://github.com/kokenamazu-boop/nama-ReaPitchMatch/raw/main/index.xml
   ```

3. `nama-ReaPitchMatch` の `nama-ReaPitchMatch.lua` をインストールします。
4. `Extensions → ReaPack → Browse packages` からスクリプトを実行するか、アクションリストに登録して実行します。

`index.xml` は `tools/build-index.mjs` がLuaのメタデータと現在のコミットから生成し、GitHub Actionsが更新します。手元で更新する場合は `node tools/build-index.mjs` を実行してください。

### 手動で入れる場合

1. [`nama-ReaPitchMatch.lua`](./nama-ReaPitchMatch.lua) をダウンロードします。
2. REAPERの `Options → Show REAPER resource path...` で開くフォルダー内の `Scripts` に置きます。
3. `Actions → Show action list → New action → Load ReaScript...` で、置いたファイルを選びます。
4. アクションリストから実行します。

このスクリプトは**1ファイルで完結**します。`lib` フォルダーなどは不要です。

## 使い方

1. タイムライン上で、音程を合わせたい**音声アイテムを選択**します。
   - 複数アイテムを選択できます。
   - 各アイテムの**アクティブテイク**が対象です。
   - MIDIアイテム、ロックされたアイテム、アクティブテイクがないアイテムはスキップされます。
2. スクリプトを実行します。
3. 「合わせたい音程」を入力します。
   - `E4`、`F#3`、`Bb2` のように、**音名＋オクターブ**で入力します。
   - MIDIエディタでノートを選択している場合は、その音が自動入力されます（異なる音程を複数選択している場合は手入力）。
   - 直前の実行で使った音程は、REAPERを閉じるまで記憶されます。
4. 必要なら「音声を解析してセント補正する」をチェックします。
   - チェック状態は次回以降にも引き継がれます。
   - 解析中は進捗バーが表示されます。`Esc` または「キャンセル」で中断できます。
5. 「適用」を押します。
6. 元に戻すときは、REAPERの `Ctrl+Z`（macOSは `Cmd+Z`）を1回押します。変更は1つのUndoブロックにまとまります。

### 時間選択で解析範囲を限定する

タイムラインに**時間選択**がある場合、選択アイテムのうち時間選択と重なる部分だけを解析します。

- フレーズ全体が1アイテムに入っている素材でも、母音や特定の音の範囲を時間選択してから実行できます。
- 時間選択の範囲外にある選択アイテムは「時間選択の範囲外です」としてスキップされます。
- 時間選択がない場合は、従来どおりアイテム全体を解析します。
- ダイアログのタイトルと上部に、解析する時間範囲が表示されます。結果にも「解析範囲」が残ります。
- ループ素材では、時間選択内で長い方のループ区間を使います。
- 解析中に時間選択を変更すると、プロジェクト状態の変化として処理を中止します。

**フレーズ素材では、時間選択を併用するのがおすすめです。** ベンチマークでは、安定した1音の区間ではYINが高精度でしたが、グライドを含む区間では一部を拾って誤補正する傾向がありました（[docs/pitch-benchmark.md](./docs/pitch-benchmark.md)）。

## ファイル名から音名を読む規則

音名は、ファイル名（拡張子を除く）の中から次の形で探します。

| 例 | 読み取る音 |
| --- | --- |
| `り_D4_30.wav` | D4 |
| `E3_あ.wav` | E3 |
| `あ_F#3.wav` | F#3 |
| `BGM_01_A4.wav` | A4 |
| `foo.A4.wav` | A4 |
| `Ｄ４.wav` | D4（全角） |
| `A4#.wav` | A#4（オクターブの後ろに♯） |
| `D4b.wav` | Db4（オクターブの後ろに♭） |
| `りD4.wav` | D4（日本語の直後も可） |

- `C#4` と `C4#`、`Bb2` と `B2b` の両方を受け付けます。
- 全角の `＃`、`♯`、`♭`、全角英数字、全角括弧などの表記ゆれを正規化します。
- `_`、`-`、`.`、`,`、空白、括弧類は区切りとして扱います。
- 音名の前後が**ASCIIの英数字**の場合は、英単語や連番の一部とみなして除外します。
  - 例：`take2.wav` の `e2` は音名にしません。
  - 例：`foo_barD4.wav` の `D4` も、直前が `r` なので音名にしません。
- 音声ファイルの拡張子（`.wav`、`.mp3`、`.flac` など）だけを取り除きます。`foo.A4` の `.A4` は音名として残します。

### ファイル名に音名がない場合

ファイル名から音名を読めないときは、**テイク名**も読みます。テイク名に `D4` などが含まれていれば、それを使います。

この動作が不要な場合は、スクリプト冒頭の次の行を `false` にしてください。

```lua
local READ_TAKE_NAME = true
```

### 音名が複数ある場合

1つのファイル名に異なる音名が複数ある場合は、誤った音へ移調しないよう**スキップ**します。

- 例：`foo_C4_G4.wav` → 「音名が複数あります（C4 / G4）」
- 同じ音名の繰り返し（`foo_C4_C4.wav`）は1つとして扱います。

ファイル名を1つの音名に直すか、テイク名を音名入りにしてください。

## セント補正について

「音声を解析してセント補正する」をチェックすると、**元の音声ファイル**を解析して、ファイル名の音名に対する実際のズレを推定します。

- 解析には、テイクのピッチ変更・再生レート・音量・FXの影響を受けない**元ソースのPCM**を使います。
- 波形の周期性から基本周波数を推定し、安定した有声音の区間だけを採用します。
- ファイル名の音名から**±50セント以内**の安定区間を探します。
- 別の音程の安定区間が混在する場合は、誤補正を避けるため**補正なし**にします。
- 推定値は0.1セント単位に丸め、`D_PITCH` に加算します。
- **区間全体がグライドしている場合**は、一部の安定区間だけを拾って補正しないよう自動で止めます。
- **80ms未満の短いアイテム**は、元ソースの手前へ最大60msだけ解析窓を広げます。前の音を拾わないよう、安定性ゲートと併用します。
- 結果には「検出 n/m・確信度 0.xx・揺れ xx cent」を表示します。mは音程が取れたフレーム数、nはそのうち音名から±50セント以内だったフレーム数です。数値が低い場合は補正の根拠が弱いため、元に戻して聴き直してください。

### 補正が入らない主な条件

- 音名が解析範囲（約70〜1100 Hz）の外
- アイテムが短すぎる（この音程の約4.5周期未満）
- ストレッチマーカーがある
- 無音、息だけ、非常に小さい音
- ポリフォニック（和音、重なった声）
- ビブラートや音程の揺れが大きく、安定区間を選べない
- 区間全体の揺れ幅が大きい（自動安定性ゲート）
- 別の音程が安定して混在している
- 元音声のPCMを十分な精度で取得できない

補正なしの場合でも、**ファイル名の音名への移調は実行**されます。結果ダイアログに理由が表示されます。

## Soloistモード

このスクリプトは、REAPERのピッチシフトモード名に `Soloist` を含むものを探し、その中でもっとも新しいバージョンを使います。

- すでに同じSoloistモードを使っているテイクは、**サブモード（詳細設定）を維持**します。
- 別のモードから切り替える場合は、サブモードを0にします。
- テイクの `B_PPITCH`（再生レート変更時にピッチを保持）を1にします。再生レートが1でないテイクでは、適用前に警告します。
- Soloistが見つからない場合は設定を変更せず、利用可能なピッチシフトモードの一覧を表示します。

### 既存ピッチ設定の警告

適用後に最終音程へ影響し得る設定がある場合、ダイアログ上部と結果レポートに注意を表示します。**自動ではスキップしません**。内容を確認してから適用してください。

- 既存の `D_PITCH` を上書きする
- 再生レートが1以外で、ピッチ保持OFFのテイク（適用すると聞こえ方が変わる）
- テイクのPitch Envelope
- テイクFX / トラックFXのピッチシフト（FX名に `pitch` または `ピッチ` を含むもの）

## 安全設計

- 音声ファイルそのものは書き換えません。変更するのはテイクのピッチ設定です。
- 変更は1つのUndoブロックにまとめます。
- 設定変更に失敗した場合は、その実行で触れたテイクの設定を元に戻します。
- 解析中にプロジェクトが変更された場合や、対象アイテムの状態が変わった場合は、適用せずに中止します。
- 解析中の状態確認は200ms間隔で行い、大量アイテム時の負荷を抑えます。
- 解析に失敗しても、移調自体は補正なしで続行します。

## レポート

結果が長い場合（20行または1500文字超）は、スクロール可能なレポートウィンドウで表示します。

- ホイール / `↑` `↓` / `Home` / `End` でスクロール
- `Ctrl+S` または「保存」で、プロジェクトフォルダーの `nama-ReaPitchMatch-report.txt` に保存
- `Esc` または「閉じる」で終了
- 短い結果は従来どおりメッセージボックスで表示します。

## 設定

スクリプト冒頭で変更できます。

| 設定 | 既定値 | 説明 |
| --- | --- | --- |
| `SHOW_SUCCESS_MESSAGE` | `true` | 完了ダイアログを表示する。連続作業では `false` にすると速い |
| `READ_TAKE_NAME` | `true` | ファイル名に音名がないとき、テイク名も読む |
| `MIN_CORRECTION_CONFIDENCE` | `0.0` | 確信度がこれ未満なら補正なし。`0` で無効 |
| `STABILITY_MAX_SPAN` | `300` | 区間全体の揺れ幅上限（cent）。超えると補正なし |
| `STABILITY_MAX_MAD` | `40` | 区間全体のMAD上限（cent） |
| `STABILITY_MIN_COVERAGE` | `0.25` | 音名±50cent内のフレーム比率の下限 |
| `STABILITY_MIN_FRAMES` | `6` | 安定性ゲートを適用する最小フレーム数 |
| `SHORT_ANALYSIS_SPAN` | `0.08` | これ未満を「短いアイテム」とみなす（秒） |
| `SHORT_ANALYSIS_PAD` | `0.060` | 短いアイテムで手前へ広げる最大秒 |
| `ANALYSIS_CHANNEL_MODE` | `"loudest"` | `"mono"` で全チャンネル平均。定位が偏る素材は `"loudest"` のまま |
| `VALIDATION_INTERVAL` | `0.2` | 解析中の状態確認間隔（秒） |

チェック状態と直前の目標音は、REAPERのExtState `Jinriki_FilenamePitch_Soloist_v1` に保存します。

- `analyze_audio`：解析チェックの状態（永続）
- `last_target`：直前の目標音（REAPERを閉じるまで）

## テスト

REAPERに依存しない関数（音名パース、ファイル名抽出、ピッチ推定、バージョン比較など）と、REAPER APIをモックした適用・ロールバック処理のテストがあります。Lua 5.4で実行してください。

```sh
lua tests/test_core.lua
lua tests/test_reaper_logic.lua
python3 tests/check_index.py
```

Luaのテストは合計41件です。`check_index.py` は `index.xml` のバージョン・作者・説明・ダウンロードURLがLuaのメタデータと一致するか確認します。GitHub Actionsでも、push時に構文チェックとテストを実行します。

## ピッチ検出ベンチマーク（開発者向け）

`tools/pitch_benchmark.py` は、FCPEで音程を付けた `nama-voices.json` を正解データとして、ReaScript内のYIN系検出を評価するツールです。ReaScript本体には含まれず、配布物の依存も増えません。

```powershell
python -m pip install numpy
python tools\pitch_benchmark.py ^
  --json-dir "D:\vst開発\jinriki\vowel-boundaries-fcpe" ^
  --rates 8000,12000 ^
  --lua "C:\path\to\lua.exe"
```

- 安定区間のセント誤差、オクターブ誤り、補正なし率を比較
- グライド区間で「補正しないべきところを補正していないか」を確認
- 8 kHz / 12 kHz、`--pad-ms` の窓拡張、`--channel loudest` などを切り替えて比較
- 外部データ不要の自己テスト：`python tools\pitch_benchmark.py --self-test --lua lua`

詳しい判定方法・実測例・制約は [docs/pitch-benchmark.md](./docs/pitch-benchmark.md) を参照してください。

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 「ファイル名から音名を読めません」 | ファイル名を `り_D4_30.wav` のようにするか、テイク名に音名を入れる |
| 「音名が複数あります」 | ファイル名の音名を1つにする |
| 「Soloistモードが見つかりません」 | REAPERのピッチシフトモードにSoloistがあるか確認する。表示された一覧も参考にする |
| 「対象アイテムの状態が変わりました」 | 解析中にアイテムを移動・削除・切り替えしない。もう一度実行する |
| セント補正が入らない | 結果ダイアログの理由を確認する。ポリフォニックや短すぎる素材では補正されない |
| 音程は合うが声が不自然 | Soloistのサブモードやフォルマント設定を調整する。このスクリプトはサブモードを維持します |
| 完了ダイアログが煩わしい | `SHOW_SUCCESS_MESSAGE = false` にする |
